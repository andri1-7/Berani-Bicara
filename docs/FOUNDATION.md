# Offline evaluation foundation (phases A–B)

Python 3.11+, standard library only. From the repository root:

```sh
python3 -m venv .venv
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m benchmarks --help
.venv/bin/python -m benchmarks status
# Optional: explicit PRIVATE literal config (never implicitly loaded)
.venv/bin/python -m benchmarks status --config /path/to/private-config
```

No command sends inference requests. `paid_dispatch_implemented` is always false. `paid_tests_enabled` reports configuration permission only; ledger `dispatch_allowed` describes accounting readiness, NOT paid authorization. Default status does not read `.env` and needs no key/network. Environment variables override explicit file values. Allowed literal keys are listed in `.env.example`; only exact `true`/`false` flags are accepted. No shell execution/interpolation; duplicate/unknown keys and ambiguous malformed literals fail closed. Do not pass credentials as CLI arguments.

Status is read-only: it opens an existing `private/ledger.sqlite3` with SQLite `mode=ro`/`query_only`, without mkdir, chmod or schema writes. A missing ledger reports `budget: {"initialized": false}`; empty/foreign databases or missing policy/schema fail closed. Only `python -m benchmarks init-ledger` explicitly creates a NEW ledger (700 directory, exclusive 600 file); an existing path is always refused. All ancestor directories are traversed without following symlinks. Existing parent directories are never chmodded; initialization requires a private immediate parent or creates one privately. Linux directory descriptors and `/proc/self/fd` anchor SQLite access; other platforms are not yet supported by this implementation. `--ledger` selects a private path; keep one canonical ledger for the entire approved envelope. Deleting/moving the ledger or deliberately selecting another one would defeat accounting and is not a reset procedure. No reset/release-contingency/raise-limit command exists. Existing policy must match on every reopen; normal restarts retain exposure.

`BudgetLedger(path, stage_limits, total_limit='5.00', stop_line='4.50')` exposes `reserve(stage, upper_usd)`, `settle(id, actual_usd)`, `mark_unknown(id)`, and `summary()`. Money inputs are decimal strings only, conservatively rounded upward to integer microUSD. Limits must already be exact microUSD. Both opening and explicit `BudgetLedger.initialize(...)` enforce immutable approved stage names and equal-or-lower caps from `DEFAULT_STAGE_LIMITS`; arbitrary evaluation stages and increased smoke caps are refused before filesystem writes. `Config.__post_init__` validates strict boolean/key types, exact monetary values, ceilings and stop-line ordering even on direct construction. Exactness does not depend on default Decimal precision. Unknown stage/contingency, outstanding request, exhausted stage/total/stop line, and halted accounts refuse reservations. `BEGIN IMMEDIATE` serializes independent processes; transactions close before control returns. Unknown/timeout reservations never expire. Once original usage is verified, `settle` can reconcile unknown requests exactly once. Full overruns are recorded even beyond $5 and permanently halt new reservations. No automatic retry exists.

Remaining/available figures are headroom, not permission to bypass outstanding/unknown/halting checks. Confirmed plus reserved is exposure; unknown is a count, not a zero charge. Generation ID column is reserved for Phase C integration; no usage metadata/network reconciliation is implemented yet.
